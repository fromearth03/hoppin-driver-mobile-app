## What shipped today

### Document upload rewired — `c5e32d7`

The backend took the proxy option from the round-7 ask and shipped
`POST /drivers/me/documents/upload` (multipart). The app now posts the bytes
in one call:

- `documents_repository.dart` — `upload()` sends `FormData` with
  `document_type`, the `file` part, and `expires_at` when the type carries
  one. `uploadUrl()` and `confirm()` are gone.
- `upload_controller.dart` — three steps collapsed to one. The 10 MB cap is
  checked *before* the upload, so a full-resolution photo fails fast instead
  of after the wait. `FileUploader` / `DioFileUploader` deleted entirely.
- The UI call site did not change — the positional signature was kept
  deliberately.

**Verified live, not assumed.** Posted a real PNG to production: `HTTP 201`,
real document id, `verification_status: pending_review`, and it persisted on
`GET /drivers/me/documents`. A text part is rejected with `400`.

### Heatmap data layer — same commit

`GET /demand-heatmap` has been live for a while and the app had no code for
it at all. Added `features/heatmap/`:

- `DemandCell` / `DemandHeatmap` models.
- `intensityOf(cell)` scales weight against the window's own `max_weight`,
  because a raw count is meaningless alone — three requests is a hotspot at
  6am and noise on a Friday night. Guards a zero max.
- Repository defaults to `hours: 24`, not the service's default of 2. On a
  launch-sized city a two-hour window is routinely empty, and an empty map
  reads as a broken one. Confirmed: `hours=24` returned zero cells while
  `hours=168` returned 12.

**No UI.** See "deliberately not built" below.

## Open — nothing is blocked on us

### Queued on the backend

Cancellation rate, payment schedule, maintenance window, notification
severity, `SESSION_REPLACED` device context, booking notes. **Do not build
ahead of these** — the app already parses the nullable fields, so each lights
up on its own when the backend ships it.

Two warnings they volunteered, worth remembering:

- Driver cancellations are recorded **without the penalty amount**, so a raw
  cancellation rate today would penalise drivers for cancellations that were
  not their fault. They are fixing the recording before publishing the
  number.
- The `payout` and `compliance` notification categories are currently filed
  as `system`, so a category filter built today would be empty.

## Two corrections from today, so they are not repeated

**Bash `grep` gave false empties in this repo.** It returned nothing, twice,
for symbols that were plainly present; the proper Grep tool found 30
references across three test files. Trusting it would have deleted
`FileUploader` while its tests still bound to it. **Prefer the Grep tool
here.**

**A "bug" in the geo parser was not one.** The flat `pickup_lat` /
`pickup_lng` shape is on the standalone `GET /rides/:id/geo`, which this app
never calls. The embedded `geo` on `GET /rides/:id` — the one the app
actually reads — is nested, carries labels, and returns `waypoints: []`,
exactly as `RideGeo.fromJson` expects. The flat shape is the rider app's
concern.

(gitignored). It is deliberately **not** in `dev.json`: the documented build
